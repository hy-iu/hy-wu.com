这个站的源码是一个 git 仓库，内容、构建、部署三层分开。记一下为什么这么搭。

## 三层结构

- **content/** —— 唯一内容源：博客是 markdown，项目是一人一个 md，调研板块（文献库 CSV、报告、图集）由导入脚本从公开仓库拉取后入库
- **scripts/build-content.ts** —— 构建时把 markdown/CSV 预渲染成**完整 HTML 页面壳**：没有 JS 也能读，搜索引擎直接可见
- **React + TypeScript（Vite 多页应用）** —— 只负责接管交互：明暗主题切换、目录表格的即时过滤

## 为什么是静态多页而不是 SPA

每篇文章、每个目录都是独立的 `index.html`（URL 即路径），深链接直接命中静态文件：

- nginx 配置基本零改动，"未知路径 404"的兜底语义保留
- 不需要客户端路由，首屏就是内容本身

## 部署

日常流程：改 `content/` → `git commit` → `./deploy.sh`（构建 + rsync 到源站目录）。构建最后一步是**隐私检查**：扫描产物，真名、真实邮箱、隧道凭据等任何一条命中即构建失败——宁可发不出去，也不带敏感信息上线。

## 署名约定

全站署名只出现 AI 模型/编码工具的名字（见页脚）。各项目的作者字段从 git 提交日志自动提取，且经双重过滤：真名硬黑名单一票否决 + 仅放行可识别的工具名——识别不出的一律留空，宁缺毋滥。
